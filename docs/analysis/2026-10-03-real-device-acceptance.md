日期：2026-10-03。**本页是原本机分析稿的脱敏摘录，只保留准备阶段的结论与分工。** 原稿保留在原工作区；本页未复制其本机路径、浏览器控制信息或认证环境。分析时“未启动”的描述属于历史状态，随后用户已授权并完成首轮核心场景；当前结果、证据和未验项统一见[同步发布与真实协作验收记录](../releases/2026-10-03-sync.md)。

## 当时采用的最小方案

| 职责 | 安排 | 能力边界 |
| --- | --- | --- |
| Agent 电脑端 | 独立可见 Chrome、专用 profile；本人完成认证后，在同一上下文操作所选记录和观察界面 | 不导出 Cookie/Token，不读取日常浏览器 profile；认证期间交回本人 |
| 用户 iPhone 端 | 普通 Chrome 与主屏幕 PWA 的安装、本人认证、少量保存、网络切换及结果回报 | 这些是物理设备操作与用户观察，不能由桌面窄屏或独立 BrowserContext 替代 |
| 真机接线后备 | 若后续排障确需检查，再确认连接、信任和对应检查器条件 | 当时设备枚举未成功，不能解释为没有连接 iPhone，也未证实可用远控；本轮未配对、变更设备设置或部署真机自动化 |

首轮采用不接线的协作方式，不以安装长期依赖、服务或购买 Apple 开发者会员为前置。桌面复用的自动化环境和真实手机回报范围见发布记录；本页不把“工具可枚举设备”写成“能控制 iPhone”。

## 准备与执行边界

1. 先锁定精确已发布候选与合同，再准备隔离桌面上下文；旧 `main` 的内容不能代表同步候选。
2. 集中确定可保留的记录与有限操作范围，由本人完成认证；使用同一上下文交接，不索取密码、Secret、subject、Cookie 或 Token。
3. 依次安排普通浏览器双向编辑、两端断网修改不同字段、草稿退出重登，再单独验证主屏幕 PWA 的登录返回与联网重开。旧验证记录导入和第二条记录另行选择，不因登录而自动认领。
4. 失败时停止后续写入，保留记录、草稿和 profile；先确认当前保存及网络状态，不通过重复保存、丢弃草稿或清站点数据排障。
5. 归档脱敏步骤与结果，区分桌面工具观察、手机用户观察和历史本地自动化；不默认采集 HAR、trace 或可能含认证参数的截图。

合同依据：[账号隔离与同步](../specs/account-sync.md)、[登录与发起环境绑定](../specs/eruoo-login-integration.md#62-浏览器--pwa-发起环境绑定)、[页面门禁](../specs/redesign.md#功能首页与页面切换)。已确认会话的页面可离线编辑，离线冷重开需联网确认会话；外部浏览器 callback 成功不能单独证明原 PWA 已登录，完成码后备仍未实现。

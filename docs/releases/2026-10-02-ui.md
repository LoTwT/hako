## 目标与执行顺序

目标沿用[首次发布单](./2026-10-02-login.md#1-候选与目标)的 Cloudflare account、单 `hako` Worker、production 和 `hako.eruoo.me`。`cloudflare.config.ts`、依赖/锁文件、DO 类/SQLite 引擎及绑定合同未变。

1. 只读核对 GitHub main、源文件和产物清单，以及 Cloudflare 当前部署、namespace、Secret 名称、域名/DNS/证书和 workers.dev。凭据需要续期时仅使用锁定 `cf` 的正常认证流程，不输出凭据。
2. 用 eruoos 提交、推送并创建 PR；用 LoTwT 查询和按既有 squash 方式合并，绑定已审阅 head。检查实际保护规则、检查状态与讨论，不绕过门禁；保留分支。
3. 读取合并提交，确认其应用/配置/锁文件与已验证产物完全对应，锁定完整 40 位候选。通过 `pnpm exec cf deploy --prebuilt --mode production` 发布，记录候选与 Worker version 的对应关系。
4. 保留远端现有 `HAKO_OWNER_SUBJECT`；锁定 CLI 的 required-secret 继承和 `keepSecrets` 路径已检查。本次不读取真实 owner、不重传 Secret、不创建新 DO 类、不删除或重建任何资源，也不改 eruoo。
5. 读回版本、bundle/资产哈希及绑定/域名状态；使用无 Cookie 的 health/session 和隔离浏览器检查公开登录门禁，不创建真实认证事务。本人真实登录、退出与 iPhone/PWA 不计作本轮已完成。

## 失败恢复

部署失败先查询实际活动版本及资源，避免把已成功上传当作未发生而重复执行。原已部署 version 为 `0a43a98f-bd7a-404f-85d4-747989e4d71b`；仅在读回确认没有 DO 类生命周期或绑定资源变化时，才可选择它恢复服务。恢复旧代码不恢复或删除 DO 数据，也会恢复旧版无登录门禁的页面行为，需一并报告影响。平台不允许直接回退时保留现有资源，以兼容当前类/绑定的修复版本前向发布；不删库或删 Worker 重建。依据：[Cloudflare 回退限制](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/#bindings)。

实际账号、域名或资源发生未预期冲突时停止相关写入并报告差异。首次发布单中已有的真实登录用户报告与未验收边界继续保留，不因本次合成测试或匿名发布检查扩大。

## 5. DO 影响与失败恢复

首次部署的类声明仅有 `HakoAccountDurableObject: { type: "durable-object", storage: "sqlite" }`。本次平台协调仅返回新增该类，读回为第 4 节的 SQLite namespace。后续同候选补齐若出现删除、重命名、转移、存储引擎变更或未知冲突，停止后续登录并保留已产生的资源，先读回状态。依据：[DO 类生命周期官方文档](https://developers.cloudflare.com/durable-objects/reference/durable-objects-migrations/)。

namespace 创建与实例 SQLite 写入是两个阶段。依据本候选代码，第一次实际调用 `owner-account` 的 RPC 会运行构造器，创建 `login_transactions`、`sessions` 及索引；有效登录发起在 discovery 成功后存入事务，成功回调原子消费事务并存入会话。前半段真实事务 RPC 已通过，本轮探针没有建立 owner 会话。本机记录/草稿没有上传或归属迁移到 DO。普通首页、health 和无 Cookie 的 session 不触发这次写入。

当前只有本次第 1 个 Worker version，没有旧版本可退，不能承诺“回退上一次已验证版本”。Cloudflare 也不允许跨 DO 类生命周期变化执行版本回退；代码回退不会恢复绑定资源的数据，旧代码与新数据结构仍可能不兼容。依据：[Workers rollbacks 官方限制](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)。

| 失败时的实际状态 | 可执行的处理 |
| --- | --- |
| 上传尚未创建 Worker | 读取平台确认结果；保留本地产物，修复凭据/连通性后可在同一授权范围重试同一候选。 |
| Worker/namespace 已创建，域名或后续步骤失败 | 保留 Worker、namespace、Secret 和全部 DO 数据。核对已完成阶段后，用同一候选/同一声明向前完成部署；不删 Worker 重建、不添加删除类声明。若需改代码或扩大资源范围，先形成新的候选及授权。 |
| 已开放域名，登录失败 | 停止后续认证操作，保留草稿和 DO 状态；根据脱敏错误修正部署接线或提出新的修复候选。需要立即停止该正式域名入口时，可撤下本次新增的 `hako.eruoo.me` Custom Domain，并核对其 DNS 与 workers.dev 关闭状态，保留 Worker、DO、Secret 和证书。此应急撤下操作必须包含在授权中；不连带删除其他记录或证书。 |
| 以后已有可用旧版本 | 先确认目标 version 存在、没有跨 DO 生命周期变化、绑定资源仍存在且数据结构兼容，才决定版本回退；不满足时采用保留现有类与数据的向前修复。 |

删除浏览器 Cookie 只影响该浏览器，不撤销服务端会话或其他设备。验收中用已实现的 logout 撤销当前会话与该环境未完成事务；不能把清 Cookie 写成完整恢复方案，也不能以清站点数据或删 DO 作为回退。

**条件性应急撤下本次新增 Custom Domain**已随本轮获得授权，当前没有触发或执行。若需紧急停止正式域名入口，仅移除第 4 节的确切绑定，随后核对受管 DNS、公网行为和 workers.dev 关闭状态；保留 Worker、DO、Secret、全部数据及证书。Custom Domain 删除不会自动删除相关证书。改变候选 SHA 的代码修复另列审阅，不预授权未知代码。
